# 仓库守望（dsh-repo-watch）

> **0.0.1 是占位版本**，只用来占住包名。真正的功能在 0.1.0。

给 DSH 装一个**常驻守望**：它盯着你的 GitHub 仓库，**只有真的有人等你时才说一句话**。

## 它解决什么

不是"我的仓库没有反馈"，而是：**我不主动去看的时候，完全不知道这些仓库发生了什么。**

真实案例：

- 一个月前你在别人仓库提的 bug，维护者回了两次、专门跑了取证实验，你没看到；
- 你在另一个仓库提的四条规则被采纳并写进文档，你一个月后才知道。

现有工具（`octobox`、`devhub`、`tj/triage`、`dinghy`）都能解决这个问题，但**都要你主动打开**。这个插件反过来：**它来找你**。

## 和它们的差别

| | octobox | devhub | triage | dinghy | 本项目 |
|---|---|---|---|---|---|
| 主动推送 | ❌ | 仅通知 | ❌ | ❌ | ✅ |
| 独立完成状态 | ✅ | ✅ | ❌ | ❌ | ✅ |
| 自动判断"谁在等我" | 人工 | 人工 | 人工 | ❌ | ✅ |
| 阈值抑制 | 人工 | 人工 | ❌ | ❌ | ✅ |
| 零操作 | ❌ | ❌ | ❌ | ❌ | ✅ |

## 设计要点

**状态机**（借 octobox 的洞察：GitHub 的已读标志不可用，打开即已读，信息永久丢失）：

```
[pending] ──我看过了──> [seen] ──处理完──> [done]
    ↑                                        │
    └──────── 有新活动（重新浮现）────────────┘
```

**推送只认 `* → pending` 的转换**，其余一律静默——没有新转换就一条消息都不发。

## 它推给你的消息长这样

推的是**一条报数**，不是内容倾泻——在手机上两秒能看完，要不要看细节由你决定：

```
有 4 条新消息（来源：GitHub）

· 需要你回复 4 条 — 有人回复了你提的 issue/PR、@ 了你，或请你 review

回复「查看」查看全部明细；「查看 1」只看需要你回复的。
最近一条：awesome-dsh-plugin/awesome-dsh-plugin#15938　Add: two IM channel plugins…（PR）
```

回「查看」之后，会话里给出带原话的明细（同一条只在聊天里展开，不再二次推送）：

```
共 4 条，显示 4 条：

1. awesome-dsh-plugin/awesome-dsh-plugin#15938　Add: two IM channel plugins…
   有人回复了你提的 PR
   fkysly（11-19）：这个 PR 的合并有冲突，我核过后手动并入了 main…
   https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pull/15938
```

**为什么不直接推明细**：一条推送里塞四条别人的长评论，读起来是负担；而"有几条、各自要什么"才是决定要不要现在处理的信息。

## 三种摘要

| 摘要 | 内容 | 怎么触发 |
|---|---|---|
| `waiting` | 需要你回复或处理的条目——报数推送里说的就是它 | 回「查看」 |
| `quiet` | **不需要你动手、但确实发生了**的事：别人在你订阅的 thread 里讨论、机器人提交等，留 30 天 | 让我「看看其他动静」 |
| `deep` | 在 `waiting` 基础上带状态、提醒次数等内部字段 | 排查时用 |
